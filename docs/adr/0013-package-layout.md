# 0013 — Restructure the flat module layout into concern packages

- **Status:** Accepted (2026-08-12; implemented the same day on branch
  `refactor/package-layout`, 11 commits, one per package + cleanup).
- **Deciders:** Dan Svoboda
- **Related:** the restructure handoff (`docs/restructure-plan-handoff.md`) that
  scoped this work; [ADR-0006](0006-unify-html-latex-renderers.md) and
  [ADR-0008](0008-docx-render-surface.md) (the render-surface architecture now
  under `rendering/`); the `.arch/` navigation layer (symlink tree + code
  browser) this makes partly redundant.

## Context

The first-party code had grown to **91 committed modules sitting flat at the
repo root** (plus a dozen untracked scratch scripts, committed as part of this
work). Nothing in the filesystem reflected the architecture; the naming
conventions (`pool_*`, `methods_*`, `genomics_*`, `render_*`, `docx_*`) implied a
structure that the directory layout did not show. The maintainer navigates code
by directory, so a flat root was a real comprehension cost.

A prior, zero-risk navigation layer already existed (`.arch/` — a gitignored
symlink tree + a syntax-highlighted HTML code browser, both generated by
`.arch-build.py`). That gave *browsing* by concern without moving files. This
ADR is the further step: **physically** moving the modules into packages so the
real directory tree reflects the architecture.

### The constraint that shaped the approach

The codebase resolves first-party imports purely via **repo-root-on-`sys.path`**
(the cwd model): `python background_server.py` from the root, and
`tests/conftest.py` inserts the root onto `sys.path`. There was no package
declaration in `pyproject.toml`. Imports were flat and absolute
(`from document_tree import X`) — **294 such statements**. Moving a module breaks
every import of it, so the move is mechanical but wide.

## Decision

**Move all 91 first-party modules into 10 concern packages, rewrite imports to
absolute package paths, and keep the cwd resolution model.** Zero modules remain
at the repo root.

The 10 packages (taxonomy validated by the pre-existing `.arch-build.py`
grouping, which already covered all modules with zero unmapped):

| package | concern |
|---------|---------|
| `web_routes/` | FastAPI app + HTTP route modules |
| `pipeline/` | pool lifecycle + processing (fingerprint→validate→integrate→process) |
| `document_model/` | the DocNode tree, template instantiation, component catalog, style vocabulary |
| `rendering/` | the shared render IR + the four emitters (HTML/LaTeX/docx/JATS-BITS) |
| `tables/` | NTP table builders + shared table formatting |
| `narrative/` | LLM + programmatic prose (background, methods, abstract, interpret) |
| `genomics/` | genomics interpretation, charts, gene bodies |
| `knowledge_base/` | bmdx.duckdb build/query + the crawl pipeline |
| `styling_export/` | docx style extraction, freeform content, provisioning, LLM endpoints |
| `tooling/` | dev/scratch/build scripts |

### How the move was executed (each package = one bisectable commit)

Leaf-first (fewest importers first: tooling → knowledge_base → tables → genomics
→ narrative → styling_export → document_model → rendering → pipeline →
web_routes). For each package: `git mv` (preserves history), a scripted
word-boundary-safe import rewrite (`from X import` / `import X` / `import X as Y`
at any indentation), then the full test suite back to baseline before committing.

Baseline held at every step: **819 passed, 6 skipped, 1 pre-existing golden
failure** (`test_process_integrated_golden` — an unrelated, documented golden
staleness that reproduces identically on `main`).

### Import model: cwd, not an installed package

`pyproject.toml`'s runtime model is left unchanged. All 12 top packages (the 10
new + the pre-existing `roundtrip/`, `pdf_text/`) import cleanly from the repo
root, so no `[build-system]`/`[tool.setuptools] packages` declaration was added —
introducing a build backend would risk behavior change for no runtime benefit.
`pip install -e .` is a future add if wanted; the app runs via
`python -m web_routes.background_server` (updated in `run-server.sh` and the e2e
launcher).

## The non-import breakages the move surfaced (all fixed)

A pure import rewrite is not sufficient; three classes of hidden coupling broke
and were repaired:

1. **`__file__`-relative asset paths (14 sites).** Modules computing paths to
   root assets (`assets/`, `templates/`, `web/`, `vocab/`, `sessions/`,
   `bmdx.duckdb`, the golden fixture, the LaTeX class file, the StyleChecker/DTD
   dirs) via `Path(__file__).parent`. Each moved one level deeper, so each was
   fixed to `.parent.parent`.
2. **String-literal `monkeypatch`/`patch` targets (11 sites).** Tests patching
   `"process_integrated.build_table_data"` etc. as *strings* — invisible to an
   import-statement rewrite. Requalified by hand (documented grep in the handoff).
3. **A `sys.modules.get()` bare-name list.** `conftest._SESSIONS_DIR_MODULES`
   looked modules up by bare name to patch `SESSIONS_DIR`; after the move those
   keys are package-qualified, so the patch silently skipped and the real
   sessions path leaked — 5 `test_session_lifecycle` failures that *passed in
   isolation* but failed in the full suite (a state-leak tell). Requalified.

## Consequences

### Positive
- The directory tree now reflects the architecture; `cd rendering/` shows the
  render layer and nothing else.
- History preserved (`git mv`), so `git blame`/`log --follow` still work.
- The move is behavior-preserving: full suite green throughout, app boots and
  serves 200 via the new `-m` entrypoint.

### Negative / accepted
- **Cross-package import cycles are now visible — and there are many.** The flat
  namespace masked them; a package-level import-graph analysis finds **8 mutual
  (2-node) cycles** and dozens of longer chains, centered on `narrative`,
  `document_model`, `pipeline`, and `web_routes`. **These are pre-existing
  coupling, not introduced by the move**, and Python resolves them fine at
  runtime (green suite). They are **deliberately ACCEPTED, not fixed, here**:
  breaking them means relocating symbols / extracting interfaces — a
  non-behavior-preserving design effort that is out of scope for a move. They are
  recorded as follow-up debt. The worst offenders (`narrative↔pipeline`,
  `document_model↔genomics`, `pipeline↔web_routes`) reflect genuine domain
  entanglement that deserves deliberate design, not a rushed tail-end extraction.
- **`report_data*` placement:** kept in `rendering/` (data-assembly *for* the
  renderers) though it also reaches into pipeline caches — a contributor to the
  `rendering`/`pipeline` coupling. Left as-is; revisit if the cycles are addressed.

### Neutral
- The `.arch/` symlink tree + code browser (which mapped flat root files) are now
  partly redundant; `.arch-build.py` should be repointed at the real package tree
  or retired (follow-up).

## Follow-ups (not blocking)
- Decouple the accepted package cycles by dependency direction (start with the
  2-cycles; likely move shared symbols to a lower layer).
- Repoint or retire `.arch-build.py` / `.arch/` now that the real tree is the
  structure.
- Optional: add a `[tool.setuptools] packages` declaration if `pip install -e .`
  becomes wanted.
- Untracked scratch scripts in the maintainer's *original* working tree that
  import first-party modules will need their imports updated post-merge (they
  were committed and rewritten on the branch, but a stale untracked copy may
  linger in the non-worktree checkout).
