# Section catalog — Phase 2: downstream dependency trace

**Status:** analysis, 2026-09-22. Companion to `section-catalog-dependency-map.md`
(phase 1). Phase 1 fixed section *identity* (which sections exist, derived from the
tree). This is phase 2: for each section, what it *depends on* at generation/render
time — observed empirically, not read by eye.

**Method.** A two-layer tracer (`tooling/section_dependency_tracer.py`) instruments
both read surfaces and composes them:

- **Layer 1 (Process, cache→payload-key):** a READ-ONLY probe — records which of the 7
  cache units are present on disk and maps each to the payload keys it feeds (the static
  `_assemble_payload` contract). It deliberately does NOT run `run_process`: that step
  PERSISTS caches as a side effect, and an earlier version of this tracer that ran it
  with placeholder params corrupted the session's captions/narratives with the "Test
  Compound" fallback (a trace must never mutate what it observes — lesson learned). The
  probe reports the 7 cache-unit-derived keys; the 3 content-prep prose keys
  (`apical_bmd_narrative`, `gene_set_narrative`, `gene_narrative`) are not cache-unit
  keyed and are documented from `_assemble_payload` rather than probed.
- **Layer 2 (Render, payload-key→section):** wraps every HTML dispatch handler in the
  node walk (`html_generator._DISPATCH` via `render_common.walk_emit`), setting the
  current section from each node's workflow key and recording the `data[...]` keys the
  handler actually reads (via a read-recording dict proxy). Also wraps
  `latex_export._load_json` to capture the session-file reads inside
  `load_session_data`. Fully read-only.

Run against **`DTXSID50469320`** (the PFHxSAm session), extended to a **maximal
document** (`tooling/build_maximal_document.py` → `sessions/DTXSID50469320/document.yaml`)
that exercises all **18** catalog node types (the global template covered 13; the
tracer's gap analysis found `cover`, `page-break`, `freeform-page`, `figure`,
`incidence-table` unexercised, and the maximal doc adds exactly those at legal parents).
Raw observations: `docs/plans/section-dependency-trace.json`.

The render layer needs no live pipeline (caches are on disk), so Layer 2 is fully
observed; the whole trace is now read-only.

Every section the catalog names, with the payload/data keys its node handlers actually

| section | node(s) | data keys read (observed) | populated from (session file / overlay) | upstream cache |
|---|---|---|---|---|
| `background` | `background` | `background` | `background.json` | — (LLM, not cache-keyed) |
| `methods` | `methods` + 21 `mm-*` | `methods` | `_cache_methods_*` → payload `methods` | `methods` |
| `animal_condition` | `animal-condition` | `unified_narratives` | `_cache_sections_*:unified_narratives` | `sections` (←`ntp`) |

| `bm2` (7 tables + incidence) | `table-*`, `max-incidence-clin-obs` | `apical_sections` | `_cache_sections_*:sections` (normalized) | `sections` (←`ntp`) |
| `bmd_summary` | `bmd-summary` | `bmd_summary` | `_cache_bmd_summary_*` | `bmd_summary` (←`ntp`+`bmds`) |
| `genomics` | `gene-sets`, `gene-bmd` | `genomics_sections`, `gene_set_narrative`, `gene_narrative`, **`overrides`, `orientations`, `breaks`** | `_cache_genomics_*` + 4 `_cache_interpretation_<organ>_<sex>_*` + `genomics_narrative_overrides.json` | `genomics`, `charts` |
| `summary` | `summary` | `summary` | `_cache_summary_generated.json` *(absent → scaffold placeholder)* | — (LLM) |

**Config sensitivity (axis 3):** all of `bm2` / `animal_condition` /
`clinical_pathology` / `internal_dose` read from the SAME `sections` cache — the
apical/organ-weight filters are applied *after* the cache read (SECTIONS schema v9 is
filter-agnostic), so a filter change re-renders without a cache miss. Structure edits
(the per-session `document.yaml`) change which nodes render but touch no cache. The
`genomics` section's `overrides` read means a per-organ narrative override
(`genomics_narrative_overrides.json`) changes its output with no reprocess.

**External resources (axis 3):** `genomics` requires `bmdx.duckdb` (knowledge base) +
kaleido/Chromium for `charts`; `methods`/`background`/`summary`/`apical_bmd_narrative`
require the LLM endpoint; `sections`/`bmds` require the Java bridge at Process time.

## 3. Findings — observed vs. expected

### F1 (confirmed, informational) — genomics reads three keys its bindings don't declare
The `genomics` node's template bindings are `genomics_sections` + the two
narrative keys. But the handler also reads **`overrides`, `orientations`, `breaks`**.
These are cross-cutting render inputs (per-node override text, landscape flags, page
breaks), not section data — but they ARE real inputs that a static
binding-only dependency model (e.g. the catalog's `node_ids`+bindings) would miss. Any
future "regenerate section X on input change" logic must treat the override/orientation
config as a genomics dependency. *This is the headline value of observing over
inferring.*

### F2 (confirmed) — four sections share one cache; no per-section invalidation
`bm2`, `animal_condition`, `clinical_pathology`, `internal_dose` all derive from the
single `sections` cache. There is no finer-grained invalidation: any input that bumps
the `sections` hash re-runs all four together. This is correct today (they are one Java
integration pass) but means "reprocess just the body-weight table" is not possible —
worth noting for any future incremental-reprocess work.

### F3 (confirmed) — `bmd_summary` invalidation is transitively chained, correctly
`_hash_bmd_summary(ntp_hash, bmds_hash)` folds in BOTH upstream hashes, so a change to
NTP stats OR BMDS results invalidates the summary. No missed edge here — the chain is
sound. (Recorded because the plan flagged invalidation as the highest-risk axis.)

### F4 (confirmed + FIXED) — reprocess never demoted the singleton LLM sections
`summary` renders from `data["summary"]`, populated from `_cache_summary_generated.json`
— absent on `DTXSID50469320` (LLM never ran), so the render degrades to the scaffold
placeholder; the *generation* path (LLM synthesis) stays unexercised in-sandbox.

Chasing summary's currency, though, surfaced a **real bug**: the reprocess/invalidate
loop that stales + currency-demotes LLM sections
(`pool_state.invalidate_pool_artifacts` and its CLI twin `pool_admin.invalidate_downstream`)
globbed only `bm2_*.json` and `genomics_*.json`. The four SINGLETON sections —
`background`, `methods`, `summary`, `bmd_summary` — are all LLM-origin
(`origin_for_section_key` → `REWRITE_LLM`, `should_stale_on_reprocess` → True) but the
glob never visited them. So on a data reprocess, a report kept claiming its
summary/background/methods/apical-BMD narrative were FINAL and approved even though the
data beneath them changed — the exact currency-BLOCK the design (ADR-0015 / phase3
currency) exists to enforce, silently defeated. This is the section-catalog pathology in
its purest form: a hand-kept file glob drifted from the true section set. The existing
characterization test never caught it because it only staged a `bm2_*` + a `genomics_*`.

**Fix (2026-09-22):** added `pipeline.session_store.iter_section_files` — the single
authoritative "which files are report sections" enumerator (the four singleton stems +
the `bm2_*`/`genomics_*` globs) — and routed BOTH loops through it. Extended
`test_invalidate_pool_stale_by_origin.py` to stage a singleton `summary` and assert it
stales + demotes (FINAL→PROTECTED) on both the server and CLI paths. Guard net green;
end-to-end check confirms all four singletons now demote while `bm2_*` stays untouched.
The summary *generation* currency (does the LLM rewrite fire) still needs a host with a
live endpoint — but the demotion/publish-block half is closed here.

### F5 (confirmed) — the 5 structural node types render but bear no data
`cover`, `page-break`, `freeform-page`, `figure`, `incidence-table` all render under the
maximal doc. Of these, only `incidence-table` (on real Clinical Observations data)
reads section data — it correctly joins the `bm2` family reading `apical_sections`. The
`figure` node's `genomics_charts` data_key is **not populated by `load_session_data`'s
overlays** — figures are wired through `chart_images`/genomics, not a top-level
`genomics_charts` key, so an authored top-level figure renders empty. Minor: authored
figures outside the genomics section have no data source today.

## 4. Missed invalidations — the defect list

Bottom line: **the CACHE hashes are sound, but the trace found and FIXED one real
demotion bug (F4).** The seven cache hashes (`ntp`, `sections`, `bmds`, `bmd_summary`,
`genomics`, `charts`, `methods`) all fold a `schema_version` and their real inputs;
`bmd_summary` correctly chains on upstream hashes (F3). Findings:

1. **(F4 — FIXED) Singleton LLM sections were never demoted on reprocess.** The
   invalidate loop globbed only `bm2_*`/`genomics_*`, skipping
   `background`/`methods`/`summary`/`bmd_summary`. Fixed via the shared
   `iter_section_files` enumerator in both `pool_state` and `pool_admin`; test extended.
   (Summary GENERATION currency — does the LLM actually rewrite — still needs a live
   endpoint to confirm on a host.)
2. **(F1) Override/orientation/break config is not a tracked reprocess input.** If a
   future path regenerates a section when "its inputs changed," the genomics section's
   dependency on `genomics_narrative_overrides.json` + orientation/break config is
   invisible to a binding-only model. Track it explicitly. (Open.)
3. **(F5) Authored top-level `figure` nodes have no data source.** Not an invalidation
   bug, but a coverage gap: `figure` outside genomics renders empty. Either wire a
   figure data_key overlay or document that figures are genomics-only. (Open.)

## 5. Reproducing

```
.venv/bin/python -m tooling.build_maximal_document DTXSID50469320 --write
.venv/bin/python -m tooling.section_dependency_tracer DTXSID50469320
# → docs/plans/section-dependency-trace.json (raw observations)
```

The maximal `document.yaml` is a tracer fixture, not a shipped default — it lives in the
session dir and only affects that session's render. Remove it to restore the global
template for that session.
